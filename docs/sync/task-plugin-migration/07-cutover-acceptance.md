# 阶段 07：兼容迁移、灰度切换与最终验收

## 顶部移植提示词

请在阶段 01–06 均通过后执行最终迁移。按平台逐一把现有 `relay/channel/task/*` 内置适配器转换为插件，优先使用官方 `plugins/tasks/*.js` 作为行为参考；不要一次性删除旧实现。为每个平台建立新旧路径对照矩阵，验证请求、响应、状态、用量、计费、退款、产物和错误 envelope 等可观察行为一致。通过配置/渠道级开关进行灰度，保留一键回滚；观察期内禁止改变进行中任务的 plugin version/generation。只有全部平台通过 e2e、跨数据库检查和运维演练后，才可删除无用旧代码并将同步台账中的 Deferred 改为 Completed。

## 迁移顺序

1. 选择一个低风险异步平台完成双写/影子对照。
2. 迁移其余平台，每个平台独立提交插件源码、fixture、usage schema、渠道配置和回滚说明。
3. 对 OpenAI Responses、OpenAI Video、native route 三类入口分别执行灰度。
4. 进行多节点 generation/revision 延迟、密钥轮换、插件回滚、数据库恢复和上游超时演练。
5. 观察期结束后，删除已被插件完全替代且无历史任务依赖的旧适配器；保留必要兼容代码。
